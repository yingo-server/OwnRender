# 二进制包使用方式

> 由 GitHub Actions 用 **Nuitka** 自动构建，每次提交都会打包发布。
> 下载地址：**仓库 → Releases**（`nightly` 为每次构建的滚动版，`v*` 为版本版）

---

## 1. 下载哪个

| 平台 | 文件 | 说明 |
|---|---|---|
| Windows x64 | `OwnRender-windows-x86_64.zip` | 解压即用 |
| Linux x86_64 | `OwnRender-linux-x86_64.tar.gz` | glibc 2.35+（Ubuntu 22.04 起） |
| Linux aarch64 | `OwnRender-linux-aarch64.tar.gz` | ARM64 服务器 / 树莓派 / 安卓容器 |
| macOS Apple Silicon | `OwnRender-macos-aarch64.tar.gz` | M 系列芯片（Intel Mac 请用源码版） |
| Android | `OwnRender-android-arm64-v8a-so-*.zip` | **`.so` 库文件**，只有参数模式，见第 5 节 |
| 文档 | `OwnRender-docs.zip` | 全部文档（中英） |

解压后的目录结构是**便携**的：

```
OwnRender-linux-x86_64/
├── ownrender            可执行文件（Windows 为 ownrender.exe）
├── background/          材质底图（可自己替换）
├── fonts/               字体（可自己替换）
├── docs/                完整文档
├── README.md  LICENSE  CREDITS.md
└── RUN.txt              快速上手
```

> 素材**不在**二进制内部，而是放在可执行文件旁边 —— 所以你随时能换字体/底图，
> 行为与直接跑源码脚本完全一致。

## 2. 三种桌面平台：与脚本用法完全一致

**解锁与运行**

```bash
# Linux / macOS
tar -xzf OwnRender-linux-x86_64.tar.gz
cd OwnRender-linux-x86_64
chmod +x ownrender
./ownrender                                  # 图形界面（TUI）
```

```powershell
:: Windows（PowerShell / CMD）
Expand-Archive OwnRender-windows-x86_64.zip
cd OwnRender-windows-x86_64
.\ownrender.exe                              # 图形界面（TUI）
```

### 参数模式：和 `python main.py …` 一模一样

```bash
./ownrender --offline-bg 微水泥 -y

./ownrender --offline-bg 微水泥 \
    --time "2025-06-21T09:00:00+08:00" \
    --lat 39.9042 --lon 116.4074 \
    --weather clear --window-orientation right -y

./ownrender --list-backgrounds
./ownrender --list-fonts
./ownrender --show-config
./ownrender --help
```

**所有参数、语义、默认值、输出文件名都与源码脚本一致**，见
[命令行参数](命令行参数.md)。区别只有一个：不用装 Python 和依赖。

### 首次运行的两个系统提示

| 平台 | 现象 | 处理 |
|---|---|---|
| macOS | 提示"无法打开，因为无法验证开发者" | `xattr -dr com.apple.quarantine ./ownrender` |
| Windows | SmartScreen 拦"未知发布者" | 更多信息 → 仍要运行（或右键属性解除锁定） |
| Linux | 权限不足 | `chmod +x ownrender` |

### 便携根目录

想让可执行文件用**别处**的素材/配置：

```bash
OWNRENDER_HOME=/path/to/my-assets ./ownrender
```

如果可执行文件旁边**没有** `background/` `fonts/`，程序会自动改用**内置**的那份
（打包时已随包携带），所以单独拷贝一个 `ownrender` 出去也能跑。

## 3. 定位适配（重点：打包版需要额外条件）

二进制包本身**不包含**任何定位服务，它靠调用系统提供的能力。各平台情况不同：

### Windows

| 方式 | 条件 |
|---|---|
| 本机 GPS | 系统**设置 → 隐私和安全性 → 位置** 里允许应用访问位置 |
| IP 定位 | 无需额外条件（`--ip-loc`） |
| 手填坐标 | `--lat/--lon`，最稳 |

### macOS

| 方式 | 条件 |
|---|---|
| 本机 GPS | 需要 [`CoreLocationCLI`](https://github.com/fulldecent/corelocationcli)：`brew install corelocationcli`；首次调用系统会弹**位置权限**，必须允许 |
| IP 定位 | `--ip-loc`，无需权限 |
| 手填坐标 | `--lat/--lon` |

> ⚠️ macOS 对**命令行程序**的位置权限较严格：若系统未授予，`--gps` 会明确报
> "全部不可用"并列出原因，此时请用 `--ip-loc` 或手填。

### Linux

| 方式 | 条件 |
|---|---|
| GeoClue | `apt install geoclue-2.0`（提供 `where-am-i`） |
| gpsd | `apt install gpsd gpsd-clients`（需接 GPS 模块） |
| ModemManager | `apt install modemmanager`（带 GNSS 的蜂窝模块） |
| IP 定位 | `--ip-loc` |
| 时区兜底 | 自动：按系统时区推算代表坐标 |

### 通用兜底（三平台都可用）

```bash
# ① 直接给坐标（最可靠）
./ownrender --offline-bg 微水泥 --lat 39.9042 --lon 116.4074 -y

# ② 把坐标写进缓存，以后用 --gps 一键命中
./ownrender --set-location "39.9042,116.4074,北京"
./ownrender --offline-bg 微水泥 --gps -y

# ③ IP 定位（多个服务结果可挑）
./ownrender --offline-bg 微水泥 --ip-loc -y
```

诊断：TUI → `信息 → 定位测试`，会列出当前环境、时区、8 个来源的可用性、
实际尝试结果、缓存与各 IP 服务返回。

## 4. 素材替换

```bash
# 换底图：把图放进 background/（png/jpg/jpeg/webp/bmp）
cp my_wall.png OwnRender-linux-x86_64/background/
./ownrender --list-backgrounds          # 确认被识别
./ownrender --offline-bg my_wall -y

# 换字体：把字体放进 fonts/（ttf/otf/ttc/otc/woff/woff2）
cp myfont.ttf OwnRender-linux-x86_64/fonts/
./ownrender --list-fonts
```

⚠️ 字体版权提醒见 [../CREDITS.md](../CREDITS.md) 与
[../fonts/README.md](../fonts/README.md)。

## 5. Android（`.so` 库文件，仅参数模式）

### 它是什么

Android 平台**不提供**图形界面，也**不是**一个能直接 `chmod +x` 跑的程序，而是
一组共享库：

```
android-so/
├── arm64-v8a/
│   ├── libpython3.*.so     CPython 运行时（由 python-for-android 构建）
│   └── libpybundle.so      本项目的 Python 模块（已冻结）
└── README.txt
```

**为什么是这种形态**：Android 上没有"独立可执行 + 自带解释器"的官方打包路径，
Nuitka 也**不支持**交叉编译到 Android。可行的官方路径是
[python-for-android](https://python-for-android.readthedocs.io/)，它产出的是
"Python 运行时 + 你的代码"这一整套 `.so`，由宿主 App 通过 JNI 加载。

### 怎么用（只有参数模式）

宿主的 Java/Kotlin 侧加载同一套运行时后，调用我们导出的参数入口
（即 [main.py](../main.py) 的 `run_args(argv)`）：

```java
// 概念示意（实际需配合 python-for-android 的 Python 运行时 / 同一 APK 内使用）
Python py = Python.getInstance();
PyObject mod  = py.getModule("main");               // 或 "ownrender_entry"
int code = mod.callAttr("run_args", new String[]{
        "--offline-bg", "微水泥",
        "--time", "2025-06-21T09:00:00+08:00",
        "--lat", "39.9042", "--lon", "116.4074",
        "--weather", "clear", "-y"
}).toInt();
```

```python
# 等价地，在 Python 侧就是一个纯参数函数
from main import run_args
run_args(["--offline-bg", "微水泥", "-y"])
```

要点：

- **没有 TUI**。无参数或非交互终端时程序会自动切到参数模式并打印 `--help`
  （这条路是专门为 Android/嵌入式调用准备的）。
- 参数、语义、输出文件**与桌面版完全一致**（见 [命令行参数](命令行参数.md)）。
- **定位**：Android 侧需宿主 App 声明并取得 `ACCESS_FINE_LOCATION`；本项目的
  定位链会依次尝试 `termux-location` → `dumpsys/cmd location` → 时区兜底。
  若宿主未授权，请用 `--lat/--lon` 或 `--set-location` 传坐标。
- 素材：把 `background/` `fonts/` 放到**可写目录**，并用
  `OWNRENDER_HOME` 环境变量或 Android 版的工作目录指向它。
- 输出目录同理（Android 上建议显式传 `-o /sdcard/...`）。

### 现实的替代方案

如果你的目标是"**在 Android 上有一个能点开就用的 App**"，而不是嵌入自己的 App：

1. 用 Termux 装源码版（`pip install numpy Pillow requests` 后 `python main.py`）；或
2. 用 python-for-android 的 `sdl2` bootstrap 自行打包成 APK（本项目已提供
   `service_only` 的构建配方，改成 `sdl2` + 一个 Kivy 界面即可）。

> `.so` 这一路线的**已知限制**：必须与构建它的那套 Python 运行时配套使用，
> 不能 `dlopen` 进任意 App。CI 里这条流水线标记为"尽力构建"，
> 若构建失败，Release 仍会照常发布三个桌面平台的产物。

## 6. CI 是怎么跑的

`.github/workflows/build.yml`，四个 job：

| job | 内容 |
|---|---|
| `desktop` | 4 个矩阵：`ubuntu-22.04`(x86_64)、`ubuntu-24.04-arm`(aarch64)、`windows-latest`、`macos-14`(Apple Silicon)。每个都做：打包 → **二进制冒烟测试（含真渲染一张）** → 上传产物 |
| `android` | python-for-android 构建 → 从 APK 提取 `.so`（`continue-on-error`，不阻塞发布） |
| `docs` | 打包 `README + docs/ + tools/` 为 `OwnRender-docs.zip` |
| `release` | 汇总所有产物 → 发布到 Releases。**推 `main` 自动更新 `nightly` 预发布；打 `v*` 标签发布正式版** |

冒烟测试不是走过场：它会真的用打包后的二进制渲一张图
（`--offline-bg 微水泥 --ssaa 2 -y`），确保 numpy / Pillow / 字体 / 素材
在冻结后仍可用。

## 7. 常见问题

**Q：二进制和源码版功能有差别吗？**
没有。三种桌面平台的二进制就是源码版的冻结形态，参数与输出完全一致。

**Q：为什么解压出来还有 `background/` `fonts/` 这些目录？**
因为素材不打包进二进制，而是随包分发在旁边，方便你替换。

**Q：`ownrender` 单独拷走能跑吗？**
能。找不到旁边的素材时会用内置那份。

**Q：Linux 报 `GLIBC_2.xx not found`？**
构建基线是 Ubuntu 22.04（glibc 2.35）。更老的发行版请用源码版或容器。

**Q：macOS 提示无法验证开发者？**
`xattr -dr com.apple.quarantine ./ownrender`

**Q：Android 的 `.so` 能放到 Termux 里用吗？**
不能。Termux 请用源码版或 Termux 自己的 Python。
**Q：macOS（Intel）有二进制包吗？**
没有。Intel Mac 的构建机（`macos-13`）已退役、长期排队，因此只发布 Apple Silicon 版
（`OwnRender-macos-aarch64.tar.gz`）。Intel Mac 请用源码版。
**Q：产物是自动更新的吗？**
是。推送到 `main` 就会重新构建并更新 `nightly`（预发布）里的 4 个桌面包、Android `.so` 与文档包；打 `v*` 标签则发布正式版。构建完会自动附上本文档。
